# M1 Foundations — Plan 2: Database Schema

Status: Completed

## Description
Wire Drizzle ORM to Neon Postgres (with the `pg` driver) and define the initial multi-tenant schema: `users`, `workspaces`, and `memberships`. Generate the first migration and verify the database is reachable.

## Goals
- Drizzle ORM + `pg` installed and configured with `DATABASE_URL`
- Schema defines `users`, `workspaces`, `memberships` (per spec §9)
- First migration generated and applied to Neon Postgres
- DB verified reachable (empty tables listed)

## Workflow
Install `drizzle-orm`, `pg`, `drizzle-kit` → create `drizzle.config.ts` → point `DATABASE_URL` at Neon Postgres → write tables in `src/lib/db/schema.ts` → generate migration → apply migration → verify with a read query.

## Implementation Steps

### Step 1: Install & configure Drizzle
- [x] Run `npm install drizzle-orm pg` and `npm install -D drizzle-kit @types/pg`
- [x] Create `drizzle.config.ts` at the project root: `dialect: "postgresql"`, `schema: "./src/lib/db/schema.ts"`, `dbCredentials: { url: process.env.DATABASE_URL }`, `out: "./drizzle"`
- [x] Create a free Neon Postgres project and set the connection string as `DATABASE_URL` in `.env`; update the placeholder in `.env.example`

### Step 2: Define the schema
- [x] Create `src/lib/db/schema.ts` using `drizzle-orm/pg-core`:
  - `users`: `id uuid primary key default gen_random_uuid()`, `email text not null unique`, `passwordHash text not null`, `name text`, `createdAt timestamp default now()`
  - `workspaces`: `id uuid primary key default gen_random_uuid()`, `name text not null`, `createdAt timestamp default now()`
  - `memberships`: `id uuid primary key default gen_random_uuid()`, `role text not null default 'owner'`, `userId uuid not null references users.id`, `workspaceId uuid not null references workspaces.id`, `unique(userId, workspaceId)`
- [x] Define `db`, `users`, `workspaces`, `memberships` type exports for typed queries
- [x] Create `src/lib/db.ts` exporting a Drizzle `db` singleton backed by a `pg` `Pool` (reuse a global pool in dev to avoid hot-reload connection leaks)

### Step 3: Migrate & verify
- [x] Run `npx drizzle-kit generate` to create the initial migration in `./drizzle`
- [x] Run `npx drizzle-kit migrate` to apply it to Neon
- [x] Verify: run `npx drizzle-kit studio` (or a one-off script) and confirm the three empty tables exist

## Functional Components

| Function | File | Role |
|----------|------|------|
| `db` (singleton) | `src/lib/db.ts` | Exports a Drizzle client over a `pg` Pool |
| `users`, `workspaces`, `memberships` | `src/lib/db/schema.ts` | Table definitions + types |

## Data Model
```ts
users:         { id uuid, email text unique, passwordHash text, name text?, createdAt }
workspaces:    { id uuid, name text, createdAt }
memberships:   { id uuid, role text 'owner', userId FK, workspaceId FK, unique(userId, workspaceId) }
```

## Boundaries
- `DATABASE_URL` → Neon Postgres (free tier).
- No auth logic yet; `passwordHash` is populated in plan 3.

## Considerations
- Auth (plan 3) uses Better Auth with its own `user`/`session`/`account`/`verification` tables (generated by `@better-auth/cli`) — no extra auth tables are defined here.
- `memberships.role` default is `owner`; other roles (member/admin) can be added later.
- pgvector is intentionally deferred: the `vector` extension is enabled in the Knowledge Base milestone (M2) when embeddings are actually stored.
- Keep a single `pg` Pool so dev hot reload does not exhaust connections.

## Execution Notes

- **Architecture** — Drizzle ORM (`node-postgres` driver) over a single `pg` Pool, configured via `drizzle.config.ts` (`dialect: postgresql`, schema at `src/lib/db/schema.ts`, out `./drizzle`). Three tables per spec §9: `users`, `workspaces`, `memberships` (uuid PKs with `gen_random_uuid()`, unique constraints, FKs, owner-role default). Types exported (`User`, `NewUser`, `Workspace`, `Membership`) for typed queries.
- **How each step was implemented**
  - Step 1: Installed `drizzle-orm` + `pg` and dev deps `drizzle-kit` + `@types/pg`. Created `drizzle.config.ts`. User created a Neon project and set `DATABASE_URL` in `.env` (value is single-quoted, which dotenv/Next handle correctly). `.env.example` placeholder already present.
  - Step 2: Wrote `src/lib/db/schema.ts` and `src/lib/db.ts` (singleton `db` + exported `pool`). Note: the plan's lowercase column names (`email`, `passwordHash`) map to snake_case DB columns (`email`, `password_hash`, `created_at`) via explicit names in `pgTable` — consistent with spec §9.
  - Step 3: `drizzle-kit generate` produced `drizzle/0000_lean_the_professor.sql` (3 tables, FKs, unique indexes). **Deviation**: `npx drizzle-kit migrate` hung on the Neon pooled connection (spinner never completed; no tables created), so the migration SQL was applied manually via a `pg` script. To keep drizzle's state consistent, the `drizzle.__drizzle_migrations` journal was seeded with the migration's sha256 hash; `drizzle-kit check` confirms "Everything's fine". Verified with a real insert → join read-back → delete roundtrip (user/workspace/membership) against the live DB.
- **Files Created** — `drizzle.config.ts`, `src/lib/db/schema.ts`, `src/lib/db.ts`, `drizzle/0000_lean_the_professor.sql` (+ `meta/_journal.json`).
- **Files Modified** — `.env` (DATABASE_URL set by user), `package.json`/`package-lock.json` (new deps).
- **Remaining / Known Gaps**
  - `drizzle-kit migrate` hangs against the Neon pooler connection string — future migrations (e.g. plan 3's Better Auth tables) should be applied via a fallback path: run `drizzle-kit generate`, then apply the SQL manually and seed the journal (or try `migrate` first, it may behave differently on the direct connection).
  - pgvector extension deferred to the Knowledge Base milestone (M2), as planned.
  - `.env` is untracked (gitignored); only the placeholder in `.env.example` is committed.
