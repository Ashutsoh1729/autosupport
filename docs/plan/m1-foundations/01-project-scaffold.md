# M1 Foundations — Plan 1: Project Scaffold

Status: Pending

## Description
Scaffold the Next.js + TypeScript application (App Router, Tailwind, src dir) with a minimal branded landing page, and get it deployed and live on Vercel.

## Goals
- Working Next.js dev server with TypeScript and Tailwind configured
- Clean base project structure (`src/`, `src/app/`)
- `.env.example` with placeholders for `DATABASE_URL` and `BETTER_AUTH_SECRET`
- Initial git commit, then a live deploy on Vercel

## Workflow
`create-next-app` generates the app → verify dev server and build → replace boilerplate with a minimal landing page → create `.env.example` → initial commit → deploy to Vercel → confirm the app loads at the Vercel URL.

## Implementation Steps

### Step 1: Scaffold the app
- [x] From the project root, run: `npx create-next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --yes`
- [x] If create-next-app refuses because of existing files, temporarily move the conflicting files out of the root, scaffold, then restore them
- [x] Start the dev server (`npm run dev`) and confirm the default page renders at http://localhost:3000
- [x] Run `npm run build` and confirm it completes without errors

### Step 2: Landing page + env example
- [x] Replace the generated boilerplate in `src/app/page.tsx` with a minimal branded landing page (product name, tagline, "Get started" button linking to `/login`)
- [x] Create `.env.example` with placeholders:
  - `DATABASE_URL=postgresql://...`
  - `BETTER_AUTH_SECRET=...`
- [x] Run `npm run build` again to confirm the changes compile

### Step 3: Initial commit
- [ ] `git add .` and commit with message `chore: scaffold Next.js + TypeScript app`

### Step 4: Deploy to Vercel
- [ ] Push the repo to GitHub and import it into Vercel (or run `npx vercel --prod` after logging in)
- [ ] In Vercel project settings, add `DATABASE_URL` and `BETTER_AUTH_SECRET` env vars (placeholders are fine for now)
- [ ] Confirm the app loads at the production Vercel URL
